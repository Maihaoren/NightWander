# NightWander

一款**纯前端**的「地图探索 + 文字终端」风格小游戏。原生 HTML / CSS / JavaScript（ES module），**零依赖、零构建**，打开网页就能玩。

> 白天在家休整，夜里出门探索。沿着道路走，探查地点、捡拾物品，天亮了回家；熬不过一夜，就会被强制送回去。

## 🎮 在线试玩

**https://maihaoren.github.io/NightWander/**

## 🕹 玩法简介

一个夜晚从 20:00 开始，到次日 06:00 天亮结束。

1. **在家**：时间不流逝，可以整理物品、查看地图。想出发就选「出发」。
2. **移动**：沿地图上的道路前往相邻地点，每次移动消耗 **1 点体力**，并消耗相应游戏时间。
3. **探查 / 拾取**：到达地点后可以选择探查或捡东西，部分行为会消耗**电量**与时间。
4. **天黑与黑暗地带**：电量会随时间流逝，待在黑暗地点流逝更快。电量归零会被送回安全屋。
5. **回家结算**：06:00 天亮、或体力耗尽、或主动回家 → 结算一夜：**天数 +1**，时间归零，体力与电量回满，然后开始下一天。

几个值得一提的机制：

- **地图探索**：已访问的地点是带名字的方块；与已访问地点**有路相连**的地点显示为可点击的菱形；其余不显示 —— 地图要靠自己走出来。
- **安全屋**：可以过夜或稍作停留。储物箱按安全屋独立存放。
- **随机事件**：触发时弹出必须决断的选项弹窗（默认关闭，可在控制台里打开）。
- **存读档**：自动存档，也支持导出 / 导入存档字符串。
- **调试控制台**：输入 `/` 开头的指令，例如 `/help`、`/area list`、`/goto area2:m1`。

## 🚀 本地运行

项目是纯静态站点，但因为用了 ES module，**必须通过 HTTP 访问**（直接双击 `index.html` 用 `file://` 打开会被浏览器的模块跨域策略拦住）。

仓库自带一个零依赖的预览服务器：

```bash
node serve.mjs 8000
```

然后浏览器打开 **http://127.0.0.1:8000/v6/**

任何静态服务器都可以，等价于 `python -m http.server`：

```bash
cd v6
python -m http.server 8000
```

```
NightWander/
├── v6/                     ← 当前版本（开发主线）
│   ├── index.html
│   ├── style.css
│   └── js/
│       ├── config.js       ← 所有可调数值
│       ├── texts.js        ← 所有文案
│       ├── state.js        ← 游戏状态
│       ├── map.js          ← 地图与区域
│       ├── timeSystem.js   ← 时间流逝
│       ├── inventory.js    ← 物品与储物
│       ├── events.js       ← 随机事件
│       ├── saveSystem.js   ← 存档序列化
│       ├── terminal.js     ← 终端渲染
│       ├── modal.js        ← 通用弹窗
│       ├── debug.js        ← 调试指令
│       └── main.js         ← 唯一的协调者
├── serve.mjs               ← 本地预览服务器
├── CHANGELOG.md            ← 更新日志（含维护规则）
└── HANDOFF.md              ← 完整开发交接文档
```

**v5/** 是上一代归档（含约 115 MB 的图片素材），已从版本库中排除，见 `.gitignore`。

## 🏗 技术特点

- **零依赖零构建**：没有 npm 包、没有打包步骤、没有 CDN 外链，`git clone` 下来就能跑。
- **模块边界清晰**：`map` 只负责地图数据不判规则、`state` 不碰 DOM、`saveSystem` 是纯函数、`main` 是唯一协调者。
- **数值与文案分离**：可调数值集中在 `config.js`，所有文案集中在 `texts.js`。
- **绝对路径无关**：所有资源引用都是相对路径，因此放在任意子路径下（如本项目部署在 `/NightWander/`）都能正常工作。

## 🚢 部署

推送到 `main` 分支后，GitHub Actions（`.github/workflows/pages.yml`）会自动把 `v6/` 目录发布为站点根目录。

也就是说，仓库根目录**不需要** `index.html`，游戏目录结构保持原样。

## 📝 版本

当前游戏版本见 `v6/js/config.js` 的 `GAME_VERSION`，更新历史见 [CHANGELOG.md](CHANGELOG.md)。

> 注意：`GAME_VERSION`（游戏版本）与 `saveSystem.js` 里的 `VERSION`（**存档结构**版本）是两套独立编号，不要混淆。
